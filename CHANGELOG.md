# Changelog

## Unreleased

- busa-shop 0.10.0: buyer login, so a customer can come back and see their own orders. With it switched on, the header shows **Account**: `/account` asks for an email, Busabase emails a 6-digit code, and the buyer sees **My orders** (order number linking to its pay page, date, items, total, status in plain words), read through Busabase's app-user `records/query` with the buyer's session, never the Orders table read with the site's key, and only those columns (an explicit whitelist: no internal note, reply draft, tracking number, address, logs, PayPal ids or cost). Plain form posts that work without JavaScript; clear messages for a code sent (check spam), waiting N seconds before another, daily limits, a wrong code with tries left, an expired code, a disabled buyer and sign-in being down. The session is the HttpOnly, Secure, SameSite=Lax cookie `busa_shop_session` (30 days); sign-out ends it on Busabase too. Orders gains **Customer account** (`customer-account`, text, empty for guests): checkout while signed in writes the buyer's app-user id there from the checked session, a guest checkout is unchanged, and an Orders table without the column still saves the order (as a guest order). Login is off until the owner's agent calls `PUT /api/v1/app-users/apps/<Shop Website node id>/settings` (`enabled`, `appName`, `ownerFields: { <Orders>: "customer-account" }`); while it is off, on a Busabase without app users (404), on the browser engine or when Busabase cannot be asked, every account link is hidden, `/account` is a friendly "not available" page and the rest of the shop works as before. `/api/status` gains `accounts`. English, German, French and Spanish texts. The manual gains "Buyer accounts (My orders, 买家登录)": switching it on, what buyers see and never see, privacy, and "A shop installed before 0.10.0". `npm run dev` now passes each Set-Cookie header on separately.

Products replaces the Image URL and More photos (one link per line) text columns with two attachment columns: **Main photo** (one picture, right after Name in both views, so the table shows thumbnails) and **More photos** (up to 11), images only, each with its own help. The manual gains "A shop installed before 0.9.0": website first (Restart, Go live), then the two columns, `--move-photos`, a probe, deleting the old columns, the Settings help and views. busa-product-hub 0.5.4 carries the same importer (its own tables keep links).
- busa-shop 0.8.0: agent commerce, so a shopper's AI assistant can find the shop's products and hand over a buy link (the course's lesson 4: in Claude, a custom connector to the shop's `/mcp`, "find me a phone under $200 that ships to Thailand, and give me the buy link"). New public documents: `/agents.md` (Shopify's agent-discovery shape: MCP address and tools, how buying works, shipping, policies), `/.well-known/ucp` (a UCP business profile advertising catalog search and lookup over `/mcp`, `public, max-age=300`, ETag, no redirect) and `/feeds/google.xml` (Google Merchant Center RSS with `g:` attributes: id, title, description, link, image and additional images, availability, price, condition, brand, gtin or `identifier_exists` no, product type, one shipping line per checkout country with transit days). `/llms.txt` links all four, `/api/status` gives `agents.mcp`, legacy post paths can no longer take these addresses, and `scripts/probe-site.mjs` checks them in the daily check. Product pages fit a phone screen: a spec value that is one long unbroken word (a 5G band list such as `n1/n3/…/n78`, a URL) now wraps, and the one-column phone layout and policy-page tables can no longer make the page wider than the screen (before, 10 of 13 real phone pages were 451–623 px wide at 390 px and scrolled sideways; `public/static/shop.css` only). - busa-shop 0.6.0: a real checkout, so the shop takes money ("起码像 Shopify 的网店"). Checkout asks for what a parcel needs (name, email, phone, full address; a state where the country needs one, a postal code where there is one), offers only countries in Settings › Ships to that have a row in the new **Shipping** table (zone, countries, cost, free from an items total, delivery time), adds that cost, and recomputes everything on the server from Products and Shipping. With Settings › PayPal `sandbox` or `live`, a client ID in Settings and `BUSA_SHOP_PAYPAL_CLIENT_SECRET` in the Space Vault (read at runtime through `GET /api/v1/vault/runtime` with the site's own key, never stored in a table), the order is saved as `awaiting-payment`, its pay page `/pay/<order id>` shows PayPal's own JavaScript SDK v6 button, and the Worker creates and captures the PayPal order itself (Orders v2, our order id as `custom_id`, the amount from the row), marking the order `paid` at capture, in the members-only preview as on the live site. Without PayPal (and on the Free plan's browser preview, which tells the owner why) checkout keeps taking order requests. **Orders** gains a lifecycle (`new`, `awaiting-payment`, `confirmed`, `paid`, `shipped`, `completed`, `cancelled`, `refunded`, `payment-problem`), the address, subtotal, shipping, PayPal ids, amount paid, refunds, a payment problem sentence, Payment and Email logs, a staff Tracking number, and the views To ship, Awaiting payment and Payment problems. The website emails over the owner's own SMTP mailbox (a small client on Cloudflare's `connect()`, implicit TLS or STARTTLS; `BUSA_SHOP_SMTP_PASSWORD` in the Vault; QQ Mail's smtp.qq.com:465 and 授权码 as the documented default): a receipt and "new paid order", or "request received" (only the shop's own data) and "new order request", or a payment problem to the owner, in the store's language, after the order is saved and never in its way. A new **Pages** table holds five published policy pages (Shipping, Returns & warranty, Privacy, Terms, Contact) in small Markdown with 【fill in …】 markers, linked in the footer and the sitemap, and a hidden draft Legal notice. The manual gains "Payments and orders (收款与订单)" (setting up PayPal from sandbox to live, webhooks only after Go live, emails, shipping, policy pages, "Selling legally (法律合规)" with official sources, shipping a paid order, payment problems) and its rules: never mark paid without PayPal, never refund, never touch the Vault.
