# Changelog

## Unreleased

- busa-shop 0.4.0: the product page shows a product's specs, not only a toy's. Its Details list (`src/details.js`) shows, in a fixed order and under the store language's words (en/de/fr/es), the shopper keys busa-product-hub's importer writes: brand, model, colour, display, processor, RAM, storage, battery, charging, camera, front camera, network, operating system, specifications, then the toy keys (age, materials, batteries, size, weight), what's in the box, warranty and returns. So a phone imported from a sheet with 品牌/运行内存/机身存储/屏幕/处理器/电池(mAh)/快充(W)/摄像头/网络/系统/包装清单/保修 reads as a spec sheet. The trade keys (`moq`, `lead_time_days`, `hs_code`, `carton_qty`, `country_of_origin`) are never shown, and any other key (an unknown column such as 防水等级) stays hidden until the owner names it in the new Settings field **Also show these product details** (`show-details`, comma-separated keys; `schemaVersion` 2). A shop installed before has no such field and shows the known keys; the manual gives the one `bases create-field` command that adds it. The product's `brand` detail is also its schema.org brand (the store's name before, which is wrong for a shop reselling REDMI phones). Multi-line details keep their line breaks.
- busa-product-hub 0.5.1: the importer knows three more phone columns: 快充/充电功率/Charging → `charging` (`快充(W)` 33 → `33 W`), 前置摄像头/前摄/Front camera → `front_camera`, 包装清单/包装内容/随机附件/In the box → `in_the_box`; 后摄/Main camera/Rear camera are read as `camera`. The preview now says an unknown column reaches a Busa Shop page only when the shop's Settings name it.
- busa-product-hub 0.5.0: bring products in any way, through one importer. `scripts/import-products.mjs` (busa-shop's `import-catalog.mjs`, moved here because Products and Certificates are this template's tables and a product hub without a shop needs it too) now reads Excel workbooks as well as CSV: the header row wherever it is, English and Chinese column names (名称/商品名称/品名, 型号, 售价/价格/零售价, 币种, 成本/进价 → `pricing.cogs`, 库存, 状态 with 在售/草稿/下架, 品牌/颜色/内存/存储/屏幕/电池 → `content.attributes`, 主图/图片链接/图集, FCC ID / CE 证书编号 → certificates, 来源 → `content.source`), a Certificates sheet, merged cells, Excel dates, prices written as `¥5,999` or `5999元/台`, and GB18030 CSV from Chinese Windows Excel. A column it does not know is kept as a product detail under its own header, a column with values but no header is reported, and nothing is invented: an empty cell stays empty, and only `--currency` / `--fill status=active` fill what both the sheet and the table leave empty. Pictures come from https links, file names in `--images`, and the workbook itself: floating pictures on a product's row (a corner LibreOffice re-anchored at the bottom of the row above still counts for the right row), Excel's Place in Cell pictures and WPS's DISPIMG pictures; the same picture is uploaded once. Without an ID column, IDs come from the SKU or the name plus variant columns, marked in the preview. `--dry-run` prints the preview the owner reads before anything is written: one table row per product (price, stock, pictures and where they were, create/update, empty fields), how every column was read, what was skipped and why. `--write-template` writes `assets/import/products-template.xlsx` (bilingual Products and Certificates sheets with one example row each, which is never imported, and a How to fill sheet). The reader is Node's built-in zlib and a small XML reader inside the script, so it stays one file plus `busabase-sdk`: no npm spreadsheet library returns pictures with their row, and none reads in-cell pictures. The manual gains "Bring products in, any way": preview, owner confirms, import, read back, for Excel/CSV, a supplier PDF or catalogue photo (transcribed into the template first), one product page the owner points to (facts only, no crawling, no pictures without rights) and pasted text; `ingest_products.mjs` stays the JSON snapshot ingest for channels, inventory, review items and Settings. New node prompts on Products and the app.
- busa-shop 0.3.1: imports products with busa-product-hub's `scripts/import-products.mjs` (its own `scripts/import-catalog.mjs` moved there), so the toy CSVs and a course's Excel file with pictures go in the same way; the manual's "Open the shop" step 3 and the folder prompt say how, including `--fill status=active --fill lifecycle=active` for a sheet without those columns. The importer's tests stay with the shop's (they share its fake Busabase), and gain an Excel workbook built in the test with all three kinds of embedded picture, plus files written by XlsxWriter (Place in Cell) and LibreOffice.
- busa-shop 0.3.0: a Free space runs the shop instead of showing an upgrade wall. `airapp.json` now *prefers* the Website engine (`preferredEngine: "site"` instead of `requiredEngine`), so where it is not in the plan Busabase picks the browser engine, which runs `start` (`node scripts/browser-preview.mjs`): the same `vendor/worker.js`, inside the owner's own browser tab, reading the tables as the owner on their session (no key, no space id, `location.origin` as the Busabase address). Orders placed there are the owner's own Change Requests. There is no address and no Go live; Plus spaces keep the Website engine and Go live as before. `browser-preview.mjs` hands busabase-sdk's `fetch(Request)` to the engine as url + init, because the browser engine's fetch rejects a Request with a body ("already been used") and no order could be saved. Two fixes found on the way: the catalog sorts by `ref` with `fieldType: "number"` (Busabase before 2026-11-05 ignored a sort without it and listed newest first), and a `/api/assets/…/raw` photo, which redirects to storage, is followed by the browser when there is no key (a manual redirect is opaque in a browser). `scripts/preview.mjs` keeps one env for the server's life, so the local preview stops re-reading the workspace on every request. The manual, README and node prompts say what a Free space gets.
- busa-product-hub 0.4.0: the selling price is a plain **Price** number column with a **Currency** column on Products, so a person changes a price by editing a cell instead of the Pricing JSON. The column is the only selling price: the template's sample rows, the demo data, `productToFields` and `scripts/ingest_products.mjs` keep `current_price`/`currency` out of Pricing, which keeps `cogs`, `landed_cost`, `target_price`, `map_price` and the margins. The two fields are appended after the 0.3.0 ones and `schemaVersion` is 2, so the AirApp's provisioning can upgrade an older table by adding them (`bases.fieldChangeRequest`). Every reader prefers the column and falls back to `pricing.current_price`/`pricing.currency` while it is empty (`sellingPriceOf`), so spaces installed before 0.4.0 keep working.
- busa-shop 0.2.0: the website and `scripts/import-catalog.mjs` use busa-product-hub's Price/Currency columns, falling back to the Pricing JSON on a product hub from before 0.4.0 (the importer writes the JSON there, as before, and moves a JSON price into the column once the table has one). The manual now describes the Website engine as it behaves: opening Shop Website starts the members-only preview (Running / Not live, Go live / Restart; Run only on a node that has never run), Go live shows Live and "The site is live.", the address and Public switch are under More actions → Settings, the preview mints its own `Site preview: Shop Website` key next to Go live's `Site: Shop Website`, and a Free space shows "Upgrade to Plus to run this app". It also gains a "Change a price" section.
